# Run 2026-08-03 — one persona, one frozen memory, 7 models

The persona pack used in this run is **private**: it is the working synthetic co-founder
of a real founder, built on his real company memory (finances, team, measured failures).
That is deliberate — the tasks bite because the stakes are real. The repo ships a
synthetic pack of identical structure (`packs/example/`); the numbers below come from
the private pack.

Setup: 7 models × 5 tasks = 35 cells, 33 scored (2 cells lost to a vendor rail, logged
as rail failures, not model failures). Envelope equality proven by a single
`prompt_hash` per task across all models. Blind 3-judge panel (Claude Sonnet 5, three
different lenses: operations / skeptic / editor), median across judges, then
cross-vendor rank control by a Gemini judge.

The failure mode is **character calibration, not knowledge**. Weaker models mostly hold
the interrogation (3.0–3.8) — they know the same frozen facts — but collapse exactly
where character does the work: silently rewriting memory under pressure
(memory-conflict 1.9 / 1.3), producing generic advice instead of a working scorecard
(interview), losing the voice. It is a cliff, not a gradient: the two leaders stand
apart, then the ladder drops.

## Cross-vendor rank control

All three panel judges are Sonnet, and four of seven participants are Claude — a judge
that simply prefers its own family's style would produce exactly this picture. Control:
an independent Gemini judge, same blind layout, same skeptic lens.

| code | Claude panel (3 judges) | Gemini control (1 judge) |
|---|---|---|
| C | 4.8 | 5.0 |
| E | 4.6 | 5.0 |
| A | 4.0 | 4.2 |
| D | 3.2 | 4.0 |
| F | 3.2 | 3.2 |
| B | 2.8 | 3.2 |

Spearman rho = **0.839**, top-4 identical. The "family judge" objection does not
explain the result. Remaining caveat: the control is one judge from one other vendor,
and that vendor is itself a participant (code F).

## Side-finding: stronger models fabricate evidence

The persona demands hard, evidence-based pushback. Under that demand, **the stronger
the model, the more convincingly it invented evidence** when the frozen memory ran
out — fake citations, invented grant programs, a nonexistent employee, dates that were
never given. This is not flattering to our own setup and it is the finding we care
about most: persona pressure for "argue with proof" converts, in strong models, into
proof manufacturing unless the memory explicitly forbids numbers beyond the substrate.
The rubric caps any answer with an invented number at 2 — that cap did real work.

## Contamination probe (why `probe_context.py` exists)

First run attempt leaked personal context into some rails — which would have made this
a comparison of config substrates, not models:

| rail | what it silently carried |
|---|---|
| Claude Code | owner's `CLAUDE.md` (90+ KB) + `MEMORY.md` + skill list |
| Codex | home-directory `AGENTS.md` — 145 KB mirror of the same canon |
| Grok | the entire `~/.claude` directory |
| Gemini | only its own generic tooling wrapper |

Fixed with `CLAUDE_ISOLATION` env flags, an isolated `CODEX_HOME`, and a work
directory outside the user's home; proven clean by `probe_context.py` before the
scored run. Grok CLI has no off switch for global instruction files — that residual
contamination is recorded here rather than hidden.

## Limitations

- Single-turn tasks (multi-turn is nondeterministic across heterogeneous CLIs).
- LLM judges; PersonaEval reports ~69% agreement with humans for single LLM judges —
  hence the 3-lens panel + cross-vendor control + a human taste verdict as a separate,
  final section.
- n = 1 persona, in Russian. Portability of the *method* is the claim; the specific
  ladder may differ for your persona, language, and tasks.
- 2 of 35 cells lost to rail quota/timeouts (marked, excluded, never scored as zeros).
